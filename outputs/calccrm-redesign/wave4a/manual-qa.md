# Волна 4a — ручной QA локального стенда

Дополнительный визуальный прогон 15.10.2026 выполнен в роли Карима на двух **локальных** PostgreSQL копиях дампа `stand_prodcopy_20260928-before-hotfix4-20261014-1909.sql.gz`: отдельно исходный `origin/stage` и ветка 4a. В копии 25 рефереров, 496 сделок, 192 возмещения, 13 договоров. Все снимки `machine-*` пересняты с этих копий: «Рефереры» показывают суммы и меню «⋯», «Сделки» — строки с реальными суммами, «Возмещения» — историю из 192 записей, «Документы» — загруженные договоры. [Сводка гейтов и ссылки на снимки](gate-summary.md). Живая база не использовалась; для визуального прогона данные не сохранялись.

Функциональный проход ниже выполнен 14.10.2026 в роли Карима на `STAND_MODE=1` до получения дампа. Для проверок использованы отдельные копии SQLite: снимки того прохода и ручное сохранение записи не затрагивали рабочие данные. В локальной базе первого прохода созданы только две тестовые сделки (`#1`, `#2`); исходные обменные записи (113), кошельки и сотрудники остались из стенда.

## Сохранение сделки без правок: дефект исходной ветки

На отдельной локальной БД открыл деталь сделки `#2`, вошёл в редактор, нажал «Сохранить изменения» без ввода. `PUT /api/deals/2` вернул 200; сумма прихода `140 242,69 USDT` и прибыль `$1 000,00` сохранились. Три поля изменились:

| Поле | Было | Стало |
|---|---|---|
| `created_at` | `2026-10-14T19:52:09.252972` | `2026-10-14T00:00:00` |
| `payout_source` | `null` | `cash_batch` |
| `payout_founder_name` | `null` | `Андрей` |

Тот же сценарий на нетронутом `origin/stage` и отдельной копии той же БД дал ровно те же изменения и тот же ответ 200. Это исходное поведение редактора. В волне 4a бизнес-логику и API не меняли; дефект передан координатору отдельно.

В разделе «Транзакции» запрос `/api/transactions/incoming` на локальном стенде возвращает 500 (`'str' object has no attribute 'get'`). Ошибка воспроизводилась до визуальных правок; загрузка списка входящих поэтому не поддаётся ручной проверке здесь.
