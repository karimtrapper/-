# Ручная сумма RUB на s6 фрихолда

База: `origin/stage@6f73714`; ветка `hotfix/s6-freehold-amount-input`.
Push/deploy не выполнялись.

Последнее изменённое поле задаёт направление расчёта, как в `syncClient`:
`syncFreeholdRate(id, 'sum'|'rate')`. При вводе суммы `amountRub` остаётся
первичной, `rates.client` хранится до 6 знаков, поле s6 показывает 4.
При вводе курса сохранено прежнее округление курса до 4 знаков и суммы до копеек.
`freeholdClientInput` добавляется только обработчиком нового ввода; миграции нет.

Согласие клиента, сводка, подготовка документов и серверный выпуск пакета
используют явную сумму, а не произведение округлённого курса и инвойса.
Сервер проверяет положительные числа и производный шестизначный курс.
Защиты version/journal/transitions не отключаются. Правила комиссии IPPS и
half-up из волны A не изменены. Для старых сделок без нового признака
сохранена прежняя обработка; GET и рендер не меняют сохранённых данных.

Контрольный пример: инвойс $97 500, клиенту 8 123 456,78 ₽.
Курс хранится как 83,317505, отображается как 83,3175.
Произведение инвойса даже на шестизначный курс даёт 8 123 456,7375 ₽,
поэтому оно не используется для восстановления согласованной суммы.
Payment Instruction и счёт содержат 8 123 456,78 ₽. Рамочный договор,
как и раньше, не содержит суммы платежа: она вынесена в приложение.

## Проверки

Тесты добавлены до реализации: Python получил 4 failed / 2 passed,
JS-тест падал на сохранении суммы. После реализации дополнены проверки
согласия клиента, реального HTML s6, старых данных, версий, журнала и переходов.

- `tests/test_s6_freehold_amount.py`: API, документы DOCX, старые данные,
  ошибочные суммы/курс и сохранение защит.
- `tests/test_s6_freehold_amount.js`: оба направления, 6/4 знака, согласие,
  сводная сумма, редактируемое поле и отсутствие записи при рендере.
- Финальный полный Python regression: **2635 passed, 36 skipped**, 231,43 с.
  Сетевой fence: 8 ожидаемых попыток, 0 неожиданных.
- Хотфикс с ролью manager: **8 passed**; focused fence: 0 попыток.
- Хотфикс + rounding/audit/API/money tests волны A: 66 passed.
- Полный JS regression: 56 passed, 0 failed, включая браузерные сценарии.

Все тесты запускаются через `scripts/run_fenced_pytest.py` и
`scripts/run_fenced_js.py`, с сохранением обязательной сетевой изоляции.
Для Python используется `/tmp/calccrm-audit-venv/bin/python`, окружение приёмки
волны A. В `/tmp/calccrm-wave1-venv` нет Telethon; первоначальный прогон в нём
не является финальной проверкой.
Для JS использован локальный Playwright и установленный Chromium 1243;
временная обёртка node передаёт путь браузера и разрешённый localhost-порт,
прочитанный из текущего профиля network.sb. Сетевые ограничения не снимаются.

Независимое ручное QA на стенде и PDF через LibreOffice не выполнялись.
Генерация и содержимое пакета проверены на DOCX, без реальных клиентских данных.

36 пропусков полного regression: 27 opt-in CRM browser, 3 PostgreSQL concurrency,
4 LibreOffice PDF, 1 browser storage, 1 Docker smoke. Эти проверки не заявляются
пройденными. Браузерные JS-сценарии из отдельного полного JS-прогона прошли.
Итоги и причины пропусков сохранены в `verification.txt`.
