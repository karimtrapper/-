# Возврат на кошелёк-плательщик (автовозмещение) — план реализации

> **Для агентов:** шаги в чекбоксах, TDD, коммит после каждой задачи.

**Цель:** приход USDT по пачке раскладывается до нуля, а сделки, оплаченные с кошелька
оунера, гасятся сами — без ручного ввода суммы и без фиктивных возмещений.

**Откуда взялось.** Схема флоу от 21.08: клиент → менеджер → связка (СБП / реквизиты) →
**оплата клиенту со своего кошелька через оунеров** → конвертация через брокера →
получение USDT на кошелёк → **отправка на кошелёк, откуда платилось за сделку**.
Выдача идёт РАНЬШЕ конвертации, значит себестоимость известна в момент выплаты,
а не после возмещения. Разбор — [wiki/pages/sber-conversion-flow.md](../../../wiki/pages/sber-conversion-flow.md).

**Боевой кейс — CNV-0002 (tradex, заявка 48):**

```
Получили          1 918,00 USDT   хеш 31655d15… → TKkeEV…
Вернуть Андрею      770,92         2 сделки Романа: 383,14 + 387,78 → TWyLcj…
Со счёта IPPS     1 101,92         #522 743,42 · #519 358,50 — возмещать некому
Остаётся у нас    1 147,08         из них маржа по Роману 45,16
```

Доли Романа из пачки — 408,04 + 408,04 = 816,08. Возврат считается по **себестоимости
выдачи**, не по доле: разница 45,16 — наша маржа. Подставить долю = отдать маржу оунеру
и обнулить прибыль сделки.

**Три исхода одной механики** (решает сравнение «куда пришёл USDT» × «с какого кошелька платили»):

| Условие | Что делаем | Как показываем |
|---|---|---|
| приход ≠ кошелёк-плательщик | реальный перевод | возмещение с ИСХОДЯЩИМ хешем |
| приход = кошелёк-плательщик | ничего не двигаем | **автозачёт**: «возмещено приходом CNV-NNNN» + ВХОДЯЩИЙ хеш |
| платили не с кошелька (счёт IPPS) | ничего | `needs_reimbursement=False`, долга нет |

**Что уже есть и переиспользуется:** `Deal.payout_wallet_id` → `Wallet`,
`Deal.payout_tx_hashes` + `_payout_transfers_total()` (app.py:6273), `PayinTx.to_address`
(тянется из сети в `attach_conversion_tx`, app.py:5445), `Conversion.wallet_id`,
`Reimbursement` / `ReimbursementTx` / `ReimbursementTxUse` с остатками,
`_close_deals_after_conversion()` (app.py:5350), `needs_reimbursement`.

**Чего нет:** себестоимость выдачи для обменных сделок не проставляется из переводов
(только для недвижки, app.py:8295/8372) · кошелёк-плательщик ни с чем не сравнивается ·
связи «пачка ↔ возмещение» нет · статуса «разнесён» нет · раскладки прихода нет.

**Ограничитель (урок инцидента #501, 21.08):** ни одна автоподстановка денег не проходит
без проверки правдоподобия. Коридор курса выдачи 25–45 ฿/USDT и неотрицательная маржа;
вне коридора — не подставляем, пишем причину в лог и оставляем ручной ввод.

### Task 1: Себестоимость выдачи известна сразу

Фундамент: пока `payout_amount_usdt` появляется только в `create_reimbursement`, любая
автоматика вынуждена гадать сумму.

**Файлы:** `app.py` (`_recalculate_deal_financials` / create+update сделки, ~6423, ~8275)

- [ ] **Тест:** обменная сделка, `payout_source=founder_personal`, `payout_tx_hashes` на
  383,14 → сразу `payout_amount_usdt=383,14`, прибыль = приход − 383,14, при этом
  `reimbursement_id is None` и сделка остаётся в списке ожидающих возврата.
- [ ] **Тест-регресс:** возмещение уже создано → повторное сохранение сделки НЕ
  перетирает `payout_amount_usdt` аллокацией из переводов.
- [ ] **Тест-коридор:** переводы дают курс 12 ฿/USDT → сумма не подставляется, поле пустое.
- [ ] Хелпер `_payout_cost_from_transfers(deal)`: `_payout_transfers_total()` + проверка
  коридора по `payout_amount_thb / cost`. Зовётся при create и update сделки,
  не трогает сделки с `reimbursement_id`.

### Task 2: Кошелёк-плательщик как адрес возврата

### Task 4: Автозачёт, когда кошельки совпали

**Файлы:** `app.py` (`attach_conversion_tx`, после `_close_deals_after_conversion`)

- [ ] **Тест:** приход пачки упал на тот же адрес, с которого платили → создаётся
  `Reimbursement(kind='auto')` с `tx_hash` = ВХОДЯЩИЙ хеш, аллокации по сделкам равны
  их себестоимости, `deal.reimbursement_id` проставлен, прибыль и агенты пересчитаны,
  статус `completed`, уведомление ушло один раз.
- [ ] **Тест:** адреса разные → автозачёта нет, сделки остаются в ожидающих.
- [ ] **Тест:** себестоимость неизвестна → автозачёта нет, в раскладке `needs_input`.
- [ ] **Тест-идемпотентность:** повторный привяз того же хеша не плодит второе возмещение.
- [ ] Вынести общий хвост `create_reimbursement` (аллокации → прибыль → `_refresh_deal_agents`
  → статус → GSheet → Telegram → webhook) в `_settle_reimbursement(db, reimb, deals, alloc)`
  и звать из обоих путей — иначе авто-путь разойдётся с ручным.
- [ ] Миграции: `reimbursements.kind` (`manual`/`auto`, default `manual`),
  `reimbursements.settled_by_payin_tx_id`.
