# Файлы стенда — приватное объектное хранилище

Ветка `stand/files-storage` от `origin/stage` **ded5b17**. Живые сделки и бакет
не использовались. Push и деплой не выполнялись.

## Изменения

- Байты вложений задачника сохраняются в приватный S3-бакет. `stand_files` содержит
  только метаданные, `object_key`, SHA256 и `deleted_at`; бинарной колонки нет.
  В `stand_state.data` остаются ссылки `storageId`, SHA256 и метаданные.
- `POST /api/stand/files` принимает multipart, добавляет файл под блокировкой
  текущей доски, проверяет действующую роль и прежние guards. Приватный черновик
  менеджера, клиентские чеки, обязательная выписка s14 и ограничения удаления
  сохранены. Нет отдельного обхода финансовых переходов.
- Существующий `GET /api/stand/file/<deal>/<kind>/<index>` проверяет сессию и доступ
  к черновику, затем отдаёт поток объекта. Ключи доступа и ключ объекта в JSON
  доски не возвращаются. Старые файлы до миграции также можно скачать.
- До **20 МиБ на файл**, до **200 МиБ уникальных вложений на сделку**, включая
  черновик. Общего лимита доски нет. `MAX_CONTENT_LENGTH` остаётся 30 МиБ:
  multipart с 20 МиБ помещается; для слишком большого запроса есть JSON-ошибка.
- PNG/JPEG/WebP в браузере уменьшаются до длинной стороны 2400 px, WebP quality
  0,85, с белым фоном для прозрачных скриншотов. Маленькое изображение сохраняется
  исходным, если перекодирование увеличивает размер. PDF не преобразуется.
- Дедупликация по `(deal_id, kind, sha256)`, включая параллельные загрузки.
  Повторная загрузка не добавляет объект/строку и показывает «Файл уже загружен».
  Старые повторяющиеся ссылки при миграции сохраняются для совместимости индексов,
  но ссылаются на один объект: байты второго паспорта не дублируются.
- Удаление ссылки новым клиентом ставит `deleted_at` в той же транзакции.
  Физического удаления объектов нет, в том числе при сбросе доски администратором.
  Отдельную процедуру физической очистки следует запускать позднее после приёмки.
- Старый PUT с base64 переносит файл в хранилище. Старые вкладки с фильтром 2 МиБ
  не могут стереть большие вложения: пропавшие ссылки восстанавливаются.
  Новый клиент передаёт `fileStorageVersion: 1`; intentional deletion проходит
  прежние проверки прав. Поддельные и чужие ссылки отвергаются.
- Пакет генератора уже хранится в `AgreementDoc`, а на доске находится `docId`.
  Его **не копируем повторно** ни в `stand_files`, ни в бакет. История выпуска,
  номер договора, подписанные вложения и замена своим документом не смешиваются.

## Переменные сервиса stand-app

Используются ровно согласованные имена:

| Переменная | Значение |
| --- | --- |
| `STAND_FILES_S3_ENDPOINT` | `https://t3.storageapi.dev` |
| `STAND_FILES_S3_BUCKET` | фактическое S3-имя из Credentials бакета, не display name |
| `STAND_FILES_S3_REGION` | `auto` |
| `STAND_FILES_S3_ACCESS_KEY_ID` | ссылка на переменную бакета |
| `STAND_FILES_S3_SECRET_ACCESS_KEY` | ссылка на переменную бакета |
| `STAND_FILES_S3_ADDRESSING` | `virtual-host` (в boto3 преобразуется в `virtual`) |

Добавлен `boto3==1.43.112`. SDK использует явные credentials, отключённые прокси,
ограниченные таймауты/повторы. Сетевой барьер стенда разрешает только точный хост
этого бакета, порт 443, на время вызова SDK в текущем потоке. Другие цели не открыты.
Тексты ошибок SDK с URL не отдаются пользователю и не логируются.

Без настроенного хранилища сервер стартует, сообщает об отложенной миграции,
новые загрузки отклоняет понятной ошибкой. Автоматической записи новых байтов в
БД нет. Локальный режим включается явно: `STAND_FILES_LOCAL_DIR=/tmp/stand-objects`;
в Railway этот режим запрещён. В автотестах используется временный каталог.

Основание для параметров: [Railway Storage Buckets](https://docs.railway.com/storage-buckets)
и [boto3 S3 configuration](https://boto3.amazonaws.com/v1/documentation/api/latest/guide/configuration.html).

## Миграция и проверка после выката

При старте, до фоновых потоков и HTTP-запросов, выполняется `_stand_migrate_files()`:
блокируется строка доски, каждый base64 декодируется, объект записывается и читается
обратно, проверяются размер и SHA256. Только после успешной проверки всех файлов
коммитятся метаданные, ссылки и новая версия доски. Повторный старт ничего не
меняет. Если перенос не завершился, исходный JSON и версия остаются прежними;
уже записанные, но не привязанные объекты не удаляются автоматически.

Реальный размер определяется по байтам, а не старой подписи размера. Исторический
автор/дата сохраняются из доступных полей; неизвестный автор обозначен `legacy`.
Существующие подтверждения оплаты/отправки чека перепривязываются только если
их отпечатки совпадали до технического переноса. Замена чека снимает подтверждение.

Перед выкатом пользователь делает бэкап БД. После выката в окружении сервиса:

```sh
python scripts/verify_stand_files.py
# Более строгая сверка с исходным stand_state.data из бэкапа:
python scripts/verify_stand_files.py --before-json /path/to/stand-state-before.json
```

Скрипт не импортирует `app` и не запускает миграции/фоновые задачи. Транзакция БД
read-only; S3 используется только для GET. Проверяется каждая активная ссылка,
существование объекта, размер, SHA256; с `--before-json` — наличие каждого исходного
файла. Ответ содержит счётчики и ошибки по идентификаторам, без паспортных данных
и секретов. Код возврата 0 означает успех, 1 — несовпадение. Для ожидаемых 16 файлов
нужно сверить `references` с бэкапом; `objects_verified` может быть меньше из-за дубля.

## Проверки

Миграция проверена на **синтетической копии структуры из 16 вложений**, включая
приватный черновик. Живые персональные данные и живой бакет в тесты не загружались.
Скачивание всех 16 файлов после миграции совпадает с исходными байтами. Проверены
идемпотентность, откат при несовпадении SHA256, обнаружение повреждённого объекта,
soft delete, отказ без S3, права, поддельные ссылки и сохранения старых вкладок.

Реальное сжатие в Chromium: **6 504 358 → 772 006 байт**, 3200×1300 → 2400×975.
Скриншот с текстом 16 px после уменьшения (12 px) просмотрен: дата, сумма,
длинный номер счёта читаются. PDF возвращается тем же объектом File.
Артефакт: `/tmp/calccrm-files-compressed-text.png`.

Для браузерного теста можно установить отдельный headless Chromium:

```sh
PLAYWRIGHT_BROWSERS_PATH=.browser-cache uvx --from playwright playwright install chromium --only-shell
```

Без установленного браузера только эта проверка пропускается; в данном прогоне
она выполнена. Сеть всех тестов ограничена fenced runners. S3 SDK проверен через
Botocore Stubber; обращения к подготовленному Railway-бакету не выполнялись.

Наборы падений по именам точно совпадают. Новых падений нет. **26 новых Python-
